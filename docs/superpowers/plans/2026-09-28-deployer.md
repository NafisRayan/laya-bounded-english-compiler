# Implementation Plan: Deployer (Developer Spec.md §8, §9, Phase 3)

Date: 2026-09-28
Status: In progress
Spec authority: `Developer Spec.md` §8 (1122-1300), §9 (1304-1367), §18.15
(2790-2835), §18.16 (2835-2903), §18.19 (2995-3044), §10.1 tier table.

## Goal

`compiler/deployer/`: create a Supabase project, wait for health, apply the
composed migrations through the Supabase CLI, configure auth, ship edge
functions, and wrap it all in the §9.2 remediation loop (classify error →
MCQ → reuse project → retry, max 3 attempts). Verbatim harnesses: §18.15
migration cleanup, §18.16 error injection with project reuse, §18.19 e2e
(skips without real credentials).

## Environment prerequisites

- `requests` is NOT installed: add `requests>=2.31` to `[project].dependencies`
  and `pip install requests` into the venv.
- The `supabase` CLI is NOT needed for tests: every `subprocess.run` path is
  monkeypatched in the verbatim tests; real pushes happen only in nightly.

## Design decisions

### D1 — package layout
`compiler/deployer/`: `__init__.py` (re-exports), `errors.py`, `supabase_api.py`,
`deployer.py`, `auth_config.py`, `edge_functions.py`, `config.py`, and
`edge_templates/{stripe_webhook,verification_webhook,notification_dispatch}.ts`.

### D2 — models & config
- `DeployResult` (pydantic): `success: bool`, `ref: str | None = None`,
  `error: Any = None`, `category: str | None = None` — exactly the fields
  §8.8/§9.2 construct.
- `config.py`: `access_token()`, `org_slug()`, `region()` reading
  `SUPABASE_ACCESS_TOKEN` / `SUPABASE_ORG_SLUG` / `SUPABASE_REGION`
  (region defaults `ap-southeast-1`); missing required vars raise
  `RuntimeError` with a setup message. `generate_db_pass()` =
  `secrets.token_urlsafe(24)`. `project_name(spec)` = `laya-<short hash of
  spec features>` — deterministic, CLI-safe.

### D3 — errors.py (§9.1, §18.16 import path)
- `class MigrationError(Exception)` (verbatim import:
  `from compiler.deployer.errors import MigrationError`).
- `classify_error(message: str) -> str`: ordered substring rules per the
  §9.1 table — `duplicate_object` ("already exists"), `rls_conflict`
  ("policy" + "already exists" checked before duplicate), `fk_ordering`
  ("foreign key constraint"), `extension_missing` ("does not exist"),
  `permission_denied`, `quota_exceeded` ("quota"/"limit"), `transient`
  (timeout/HTTP 5xx/503), `sql_syntax` ("syntax error"), else `unknown`.
- `RETRYABLE`: transient, duplicate_object, rls_conflict, fk_ordering,
  extension_missing (per §18.16 `should_retry` column).
- `remediation_options(category, spec, error) -> list[dict]` of
  `{"label": ..., "value": ...}` MCQ options per §9.3 (fk_ordering:
  reorder/combine/remove relationship; quota_exceeded: upgrade/remove
  features/manual; extension_missing: enable/skip; duplicate_object,
  rls_conflict: retry-after-fix note; others empty → early return path).
- `apply_remediation(spec, category, answer) -> BackendSpec`: pure spec
  transform (extension enable → record decision; feature removal → drop
  flag; everything else returns spec unchanged — composition is already
  deterministic/idempotent, so SQL-side fixes live in the fragments).

### D4 — deployer.py import surface (monkeypatch contract)
§18.16 does `monkeypatch.setattr(deployer, "<name>", fake)` for
`create_project`, `wait_for_healthy`, `link_project`, `apply_migrations`,
`present_mcq`. Therefore `deployer.py` does `from .supabase_api import
create_project, wait_for_healthy`, defines `link_project`/`apply_migrations`
(§8.3) and `present_mcq` in-module, and `deploy_with_remediation` calls them
as module globals. It imports `subprocess` as a module attribute (§18.15
patches `compiler.deployer.deployer.subprocess.run`).

### D5 — apply_migrations (§8.3 verbatim semantics)
rmtree stale `supabase/migrations`, rewrite all files from `Migration`s,
`supabase db push --include-all` with `SUPABASE_DB_PASSWORD` in env;
returncode != 0 → `MigrationError(stderr)`.

### D6 — final return carries the last category
§9.2's literal final return omits `category`, but verbatim §18.16 asserts
`result.category == expected_category` for ALL rows including ones that
exhaust attempts. So the max-attempts return is
`DeployResult(success=False, error=<last error or message>,
category=<last category>, ref=ref)`. Deviation from §9.2's letter,
required by §18.16.

### D7 — transient retry
`time.sleep(2 ** attempt)` then `continue` (project is reused; §9.4 cap is
the loop bound, default `max_attempts=3`).

### D8 — deploy_spec (§8.8) with default ontology
Signature `deploy_spec(spec, ref, db_pass) -> DeployResult` (§18.19 calls it
with three args). `compose(spec, ontology)` uses a cached
`load_ontology(compiler/ontology/versions/v1)` default. Sequence:
apply_migrations → configure_auth → deploy_edge_functions →
`DeployResult(success=True, ref=ref)`.

### D9 — edge_functions.py (§8.7 verbatim semantics)
Templates dir = `compiler/generator/edge_templates` (spec's path). Scaffold
only touches managed function dirs; unknown name → `ValueError`;
`deploy_edge_functions` no-ops when `spec.edge_functions` is empty.
Templates are minimal but functional Deno handlers (stripe signature
verification stub, verification webhook, notification dispatch).

### D10 — e2e harness (§18.19)
`tests/e2e/conftest.py` defines `temp_supabase_project`: skips unless
`SUPABASE_ACCESS_TOKEN` and `SUPABASE_ORG_SLUG` are set; otherwise creates a
real project, yields `{"ref", "token"}`, deletes it on teardown. Module
carries `pytestmark = pytest.mark.slow`. Verbatim test body otherwise.

## Test files to create

- `tests/unit/test_deployer_errors.py` — classify_error for all nine §9.1
  rows; retryable set; remediation option shape; apply_remediation returns a
  valid spec; DeployResult fields.
- `tests/unit/test_deployer_auth_config.py` — payload per auth method
  (email_password / oauth_google / magic_link / oauth_github) against a
  patched `requests.patch`; URL shape.
- `tests/unit/test_deployer_edge_functions.py` — scaffold writes templates,
  removes stale managed dirs, unknown function raises, deploy no-op on empty
  list, `_managed_function_names` == 3 templates.
- `tests/unit/test_deployer.py` — apply_migrations writes + clears stale +
  raises MigrationError (patched subprocess); link_project passes env;
  deploy_spec happy path with patched collaborators; transient backoff
  (patched time.sleep).
- `tests/integration/test_migration_cleanup.py` — §18.15 verbatim.
- `tests/integration/test_remediation.py` — §18.16 verbatim.
- `tests/e2e/conftest.py` + `tests/e2e/test_full_pipeline.py` — §18.19
  verbatim (+ fixture; skips without credentials).
